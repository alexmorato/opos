# **Tema 71. Ciberseguridad Aplicada al Cloud - Resumen Ejecutivo**

## **1. Modelos de Servicio Cloud (IaaS, PaaS, SaaS)**
- **IaaS (Infraestructura):** Cliente gestiona SO, apps, datos. Proveedor: hardware, red, virtualización. (Ej: AWS EC2, Azure VMs). **Responsabilidad compartida:** cliente desde el SO.
- **PaaS (Plataforma):** Entorno para desarrollar/desplegar apps. Proveedor gestiona infraestructura y plataforma. (Ej: Google App Engine, Azure App Services). Cliente gestiona app y datos.
- **SaaS (Software):** Software completo en la nube. (Ej: Office 365, Salesforce). Proveedor gestiona casi todo. Cliente: datos y configuración.

## **2. Modelos de Despliegue**
- **Pública:** Recursos compartidos multi-tenant. Eficiente, escalable, pero menos control.
- **Privada:** Infraestructura exclusiva (on-premise o alojada). Mayor control y seguridad, más coste.
- **Híbrida:** Combina pública y privada. Permite "cloud bursting". Complejidad de gestión y seguridad.
- **Comunitaria:** Varias organizaciones comparten infraestructura con necesidades comunes.

## **3. Principales Amenazas (Cloud Security Alliance - Top Threats)**
1. **Violación de datos y filtración**
2. **Gestión deficiente de identidades, credenciales y accesos**
3. **Interfaces y APIs inseguras**
4. **Vulnerabilidades del sistema**
5. **Secuestro de cuentas (Account Hijacking)**
6. **Insiders maliciosos**
7. **APT (Advanced Persistent Threats)**
8. **Pérdida de datos**
9. **Falta de diligencia debida en la adopción**
10. **Abuso y uso nefasto de servicios cloud**

## **4. Modelo de Responsabilidad Compartida (Shared Responsibility Model)**
- **SIEMPRE del proveedor:** Seguridad física del data center, hardware, infraestructura de red.
- **SIEMPRE del cliente:** Datos, gestión de usuarios y accesos, políticas de seguridad.
- **Variable según el servicio (IaaS/PaaS/SaaS):** Sistema operativo, red, aplicaciones.
- **Regla clave:** "El cliente es siempre responsable de la seguridad EN la nube, el proveedor de la seguridad DE la nube."

## **5. Pilares Fundamentales de Seguridad Cloud**
- **Cifrado:** De datos en reposo y en tránsito. Gestionar claves (BYOK - Bring Your Own Key, HYOK).
- **Gestión de Identidad y Acceso (IAM):** Mínimo privilegio, MFA (Autenticación de Factores Múltiples), SSO (Single Sign-On), directorios híbridos (Azure AD, AWS IAM).
- **Gobernanza y Cumplimiento:** Políticas de uso aceptable, auditorías continuas (CASB - Cloud Access Security Broker), cumplimiento normativo (GDPR, ENS, Esquema Nacional de Seguridad).
- **Protección de Red:** Firewalls (WAF - Web Application Firewall), segmentación (VPC, VNet), VPN/ conexiones privadas (Direct Connect, ExpressRoute), DDoS.
- **Resiliencia y Continuidad:** Backup (3-2-1 rule), recuperación ante desastres (DRaaS), alta disponibilidad entre zonas/regiones.

## **6. Consideraciones Específicas para Administración Pública (Ayuntamiento)**
- **Soberanía de datos:** Almacenamiento en territorio UE/España.
- **Cumplimiento legal:** ENS (Esquema Nacional de Seguridad) nivel alto/bajo, LOPDGDD, Ley 40/2015 de Régimen Jurídico Sector Público.
- **Proveedores cualificados:** Preferencia por proveedores con certificaciones del CCN (Centro Criptológico Nacional) o que cumplan ENS.
- **Contratación:** Especificaciones técnicas en pliegos para garantizar seguridad, propiedad de datos y portabilidad.
- **Monitorización centralizada:** Gestión unificada de logs y eventos (SIEM en cloud) para detección y respuesta.

## **7. Buenas Prácticas Imprescindibles**
1. **Inventariar y clasificar** todos los datos y cargas de trabajo antes de migrar.
2. **Asegurar la configuración:** Errores de configuración son la causa #1 de incidentes. Usar herramientas de "Cloud Security Posture Management" (CSPM).
3. **Monitorizar actividad anómala** en accesos y uso de recursos.
4. **Planificar respuesta a incidentes** específica para cloud (contención en entorno multi-tenant).
5. **Formar continuamente** a personal técnico y usuarios en concienciación cloud.
6. **Leer y entender** el Acuerdo de Nivel de Servicio (SLA) y las responsabilidades.
7. **Diseñar para "fallo seguro"** (arquitecturas resilientes).
